# FORMA: план реализации

Цель: работающий MVP онлайн-записи согласно specification.txt.
Архитектура: pnpm monorepo, React/Vite → /api/v1 NestJS → Prisma/PostgreSQL.
Исполнение: в текущей сессии, самостоятельно; отдельная итоговая проверка кода.

## Решения

- Имя салона и контакты выдаёт /config. KZT, Asia/Almaty заменяются env.
- Временные интервалы полуоткрытые. Temporal с disambiguation=reject исключает неоднозначное и отсутствующее локальное время.
- Порядок блокировок: Service (при бронировании FOR SHARE, редактировании FOR UPDATE), затем Master (FOR UPDATE), затем запись. Изменение набора услуг блокирует только Master и не блокирует Service.
- Дополнительно EXCLUDE GiST защищает все неотменённые интервалы.
- Сессии: случайный токен, SHA-256 в БД, HttpOnly cookie. CSRF: точный Origin плюс обязательный пользовательский заголовок на всех изменяющих запросах, CORS отключён.
- Одно рабочее окно в день. Расписание изменяется атомарно; будущее подтверждённое посещение нельзя вытеснить.
- Новый GitHub-репозиторий по умолчанию private; публичность можно изменить позже.
- Docker отсутствует в окружении: локальные проверки используют отдельный кластер PostgreSQL 17; Compose проверяется статически.

## Этапы и проверки

- [x] 1. Workspaces, схема, SQL-миграция, чистый модуль доступности. Unit: буфер, границы, 30 минут, 60 дней, DST, часовой пояс, отмены.
- [x] 2. NestJS: сессии, DTO, роли, транзакции, каталог, админка. HTTP integration на изолированной БД: 1×201 + 1×409; 10 запросов; пересечения с разными началами; разные мастера; два приложения.
- [x] 3. React: главная, каталог, wizard, login/register, кабинет, админка, 404. Только реальный API; query keys включают все параметры; выбор хранится в URL.
- [x] 4. Seed, Docker, CI, документация, ERD. Seed повторяемый и не перезаписывает реальные данные.
- [x] 5. Build/typecheck/lint/unit/integration/Playwright. Проверки 375/768/1440, скриншоты четырёх страниц, независимое ревью.
- [ ] 6. Git commit, новый GitHub repo и push при доступной авторизации. Запуск локального продукта, итоговый отчёт с фактическими результатами.

## Особое внимание

Неверные UTC offsets; параллельное изменение цены и расписания; чужие записи; повторная отмена; сеть и устаревший выбранный слот; пагинация/границы диапазона; мобильное переполнение.
